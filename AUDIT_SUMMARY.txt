ERROR HANDLING AUDIT: Backward Navigation & Submission Flow
=============================================================

SCOPE: Full review of error handling in form navigation, draft loading, ASC autofill, 
       file uploads, and submission finalization.

SEVERITY BREAKDOWN:
- 4 CRITICAL issues (silent failures, state corruption, data loss)
- 6 HIGH issues (poor error handling, missing validation)
- 3 MEDIUM issues (UX problems, stale state)

KEY FINDINGS:

CRITICAL ISSUES:
1. ASC autofill failures are completely silent (line 130-146 submit/page.tsx)
   → Users don't know when metadata refresh fails
   
2. Draft loading fails without error notification (line 84-110 submit/page.tsx)
   → Users land on empty form with no indication draft failed to load
   
3. Backward navigation during upload corrupts state (line 217 submit/page.tsx)
   → User can click Back during upload, leaving refs in broken state
   → Prevents future submissions due to submittingRef.current flag
   
4. Upload-URLs API errors don't prevent partial submission creation
   → If URL generation fails mid-request, submission left in corrupted state

HIDDEN FAILURE PATTERNS:
- 12+ network failures completely unhandled
- 8+ validation errors silently ignored
- 5+ async race conditions with no guards
- 3+ places where refs stay set after errors
- No error logging with unique IDs for Sentry tracking

USER IMPACT:
- Users get stuck unable to submit (submittingRef.current stuck true)
- Draft data silently lost when navigation fails
- ASC autofill appears to work but silently fails
- File uploads can complete but state becomes incoherent
- No way to know what went wrong or recover
